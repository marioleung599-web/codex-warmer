# Codex 自动预热

基于 [viseshb/claude-codex-warmer](https://github.com/viseshb/claude-codex-warmer)，MIT 许可证。

- 只运行 Codex，每半小时检查一次。
- 五小时窗口仍在运行时跳过；窗口结束后发送简短请求。
- 自动请求至少间隔 5 小时 1 分钟；手动测试会立即发送请求。
- 同时只允许一次运行；每次运行最多 10 分钟。
- 明确检测到没有五小时窗口，或周额度耗尽时，自动检查跳过。
- 每天更新一次运行时间记录，让定时任务保持活跃。
- GitHub 定时运行可能延迟，不能保证窗口结束后立刻预热。

## 待完成设置

任务启用前，必须配置两个 GitHub Actions Secrets：

1. `CODEX_AUTH_JSON`：Codex 当前登录凭证，只能通过 Secrets 保存，不能放进代码、聊天或公开日志。
2. `GH_PAT`：只允许本仓库的 Secrets 读写权限，用于保存 Codex 自动更新后的登录凭证。

仓库只公开程序及时间记录，凭证通过 GitHub Secrets 存储。

## 登录凭证的实际限制

上游 README 的“登录两次分离凭证”建议已经被其 2026-08-14 的代码注释纠正。不要照着旧 README 登录两次。

作者报告：本地重新登录可能使云端凭证失效；本地与云端也可能因轮换凭证而互相影响。自动回存凭证能减少云端自己的失效，但不能保证与本地并行使用永不冲突。遇到认证失败，需要重新配置 `CODEX_AUTH_JSON`。

## 停止任务

在 GitHub 仓库的 Actions 中选择 `codex-window-warmer`，通过菜单选择 Disable workflow。

## 验证

配置格式已经本地检查。只有云端测试成功、且账号额度显示符合预期的重置时间后，才能确认预热有效。
